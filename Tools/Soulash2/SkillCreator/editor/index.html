Skill / mod.json

Official docs §5.1: starting_gear (first always grants, first+second is a create choice). Docs exp_sources are incomplete; the dropdown is mined from core_2 + workshop skills.json (e.g. walk, carve, production, trade). thumbnail is a 4:3 PNG for Steam. disable_portraits is global and overrides other mods — leave it off. File name is still ability_amplifiers.json (docs wrongly say amplifiers.json).

Stat points

Milestones stay on their unlock levels. The engine allows +1 statistic on the same level. Default keeps early vanilla stats (2, 4, 5, 7, 8, 10) then every level 11–49. Vanilla Pyromancy interleaves some empty post-10 levels, which is why a milestone can show with no +1. Filling 11–49 does not move anything.

Thematic 32×32 sheets: python s2_skill_cli.py generate-icons --id … --overwrite (starts the SD server; use --no-sd for procedural). write does not generate art.

Production actions

Docs §9: clone a vanilla action (Cut Wood / Mine / Harvest). Id needs a mod prefix. Producer entities are still out of scope — this only writes character.json production_actions. Milestone kind is production_action.

Add unlock

Empty description becomes ::damage ::damage_type when damage is set (docs §6.2). Entity cost / item type / ammo: JSON tab or add-ability --cost-item --cost-item-type --ammo.

Spell triggers use the documented passive effect trigger_ability_on_cast. Recursive chains are allowed by the data model but can keep scheduling casts; validate flags cycles for review.
